# Дані, згода, валідність і походження

## Фактичний стан на момент створення starter

**Немає жодного наданого реального набору подій/згод/UX-протоколу.** У папці є лише явні синтетичні приклади, що не підтверджують ефективність методу.

## Принципи

- Дослідницький режим має вимкнутий збір за замовчуванням. Лише явна opt-in дія після пояснення мети, типів подій і строку зберігання. Відкликання зупиняє збір і пропонує видалити записані події.
- Не зберігати email/ПІБ, конкретну IP-адресу, значення полів форм, `localStorage` з приватною інформацією, URLs із query, cookies, повний user-agent, геолокацію.
- Псевдонімізація не дорівнює повній анонімізації; дотримуватися принципу мінімізації та реальних локальних правил обробки даних. Потрібне погодження досліду з керівником/кафедрою за їх процедурами.
- Дані мають `source=synthetic|volunteer` та `is_synthetic=true|false`; заборонити змішування джерел. Для `volunteer` забезпечити запис версії форми згоди й часу; не записувати персональні реквізити згоди.
- TTL подій конфігурований, наприклад 30 днів для прототипу (як **проектне рішення**, не правова вимога). У README точно пояснити механіку видалення.
- Для реального імпорту потрібен manifest із описом походження, згоди та обмежень; валідатор має відхиляти небезпечні й невідомі колонки.

## Доменні контракти

`contracts/events.schema.json`: безпечні події (строге перерахування, `additionalProperties=false`).
`contracts/preference_labels.schema.json`: явна добровільна мітка, час формування ознак має бути раніше за `decision_at`.
`contracts/trials.schema.json`: реальні/синтетичні дослідницькі спроби.
`contracts/prediction.schema.json`: прогноз та рішення політики.

## Data leakage — тести-інваріанти

- Жодні події з `timestamp >= decision_at` не доступні feature builder.
- `participant_id`, `session_id`, `future_score`, `trial_completed`, `elapsed_ms` і `preferred_layout` не є ML-features.
- У train/val/test множини participant_id попарно не перетинаються.
- Якщо один клас відсутній у validation/test, метрика, що його вимагає, не вигадується: виводити відмову або undefined with reason.
- Ідентичний `seed` та вхідні дані дають еквівалентні вихідні таблиці/значення в межах задекларованих чисельних допусків.
