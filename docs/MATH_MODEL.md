# Формалізація методу для підрозділів 2.1 і 2.5 (початковий варіант)

Це **специфікація запропонованого алгоритму**, не твердження про вже доведену ефективність. Після експериментів потрібно зафіксувати фактично використані формули й параметри.

## Позначення

- `u` — псевдонімний учасник (жодних PII).
- `t` — момент прийняття рішення; історія `H_u(< t)` містить лише дозволені події до `t`.
- `x_u,t = φ(H_u(<t), context_t)` — вектор агрегованих pre-decision ознак.
- `L={standard,compact,focus}` — множина перевірених компонувань.
- `l_current` — поточний макет.
- `p_theta(l | x)` — оцінена моделлю ймовірність **явної переваги** макета `l`; вона **не** є математично доведеною ймовірністю зменшення часу виконання задачі.
- `C(l,l_current)` — заздалегідь визначена вартість перестановки (наприклад, частка віджетів, що змінили позицію; 0 для незмінного макета).
- `G(l) = p_theta(l|x) - p_theta(l_current|x)` — різниця модельних оцінок переваги.

## Вибір кандидата

`l* = argmax_{l∈L} [p_theta(l | x) - λ·C(l, l_current)]` за умови, що макет містить всі основні можливості й доступні дії. Конфігурація `λ` задається на validation, не test. При рівності обирати `l_current` для стабільності.

**Політика рішення**: якщо немає явної згоди на персоналізацію, модель відсутня, обсяг попередніх подій < `min_events`, є active_task, `max_l p_theta(l|x) < min_confidence`, `G(l*) < min_probability_gain` або не сплив cooldown — повернути `no_change`. Інакше `propose(l*)` без автоматичної зміни. Зміна реалізується лише за `user_accept`; rollback за `undo`.

## Базові моделі

- Static: `ŷ=standard` завжди.
- Rule: прозоре правило, сформульоване до експерименту; наприклад, високі `quick_actions_7d` → `compact`, значуща перевага `opens_tasks_7d` → `focus`, інакше `standard`. Пороги задаються за train-only і залишаються фіксованими.
- Logistic regression / Random Forest / XGBoost: `ŷ = argmax p_theta(l|x)` з однаковими ознаками та розбиттям.

## Основні оцінки

`Accuracy = correct / n`; `Macro-F1 = (1/|L|) Σ_l 2·precision_l·recall_l/(precision_l+recall_l)` за визначенням нульових знаменників відповідно до прийнятої реалізації. `LogLoss = -(1/n) Σ_i log p_theta(y_i|x_i)`, лише для коректних probability models. За браком необхідної кількості класів/учасників не генерувати числа.

Для UX порівняння вимірюється **медіана** `elapsed_ms` і `click_count`, success rate та rate скасувань у дійсних експериментальних умовах; не замінювати це метриками класифікації.

## Абляційний дизайн

A0 `ML only`, A1 `ML + confidence/gain thresholds`, A2 `ML + thresholds + stability constraints + explicit confirmation`. У synthetic replay можна порівняти частоти рекомендацій/відмов/перемикань, але **реальну корисність** перевіряють окремо з людьми.
