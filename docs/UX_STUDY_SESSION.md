# Протокол одного контрольованого досліду з людиною

Перед початком отримати погодження процедури відповідно до вимог кафедри, пояснити мету й добровільність та зафіксувати consent. Не зберігати справжнє ім'я або контакт в експериментальній таблиці.

1. Призначити випадковий псевдонім учасника та записати групу / порядок проходження умов за збалансованим планом (для трьох умов застосувати чергування ABC/BCA/CAB, якщо можливо — всі 6 перестановок).
2. Усі умови мають однаковий функціональний набір задач, змінюється тільки схема UI/політика вибору. Інтерфейс має бути знайомим перед стартом вимірювань; однакова тренувальна інструкція.
3. Учасник виконує завдання `find_task`, `open_report`, `use_quick_action`. Фіксувати `elapsed_ms`, `click_count`, `completed`, `error_count`, `sequence_index`, mode `static|rule|hybrid`, `layout_variant`.
4. Модель і пороги заморозити до UX-сесій. Для `hybrid` запускати тільки рекомендацію з preview + підтвердженням; випадки відмови також фіксувати.
5. За окремою згодою можна провести стандартизоване SUS; якщо запитань менше ніж 10 або скоринг не підтверджено — не називати результат SUS.
6. Після завершення перевірити повноту trial log, а також кількість учасників та порядок умов. Реальні статистики формуються лише з перевірених спостережень.
7. Записати обмеження: малий N, нетиповий склад учасників, ефект навчання, відмінність задач від реальних бізнес-процесів, суб'єктивність labels, загрози приватності.

Заборонено фабрикувати учасників, кількість спроб або вигадані результати анкет навіть для ілюстрації наукової частини.
